# File structure

Structure fixes from the code quality review of 2026-11-20, with no change in
behaviour: long functions get named parts, and code moves to the file a reader
would look in.

- Providers (`src/providers/`): the parts Deepgram and Mistral repeat around
  their socket, such as reading a message or warning that it cannot be read, and
  the check of the buffered audio, are shared from `messages.ts` and
  `provider.ts`. Each provider's message handling moves out of the body of its
  `connect`, so `connect` reads as opening a stream. No base class.
- `src/auth.ts`, new: the token check of `server.ts` (the token from the
  subprotocols, its check and the reason for a refusal; `architecture.md`,
  Authentication).
- `src/js-files.ts`: serving a dicta-js file with its ETag and `304` moves here,
  next to loading the files.
- `src/server.ts`: the limits of a connection (the idle timer, the age timer,
  the real-time count and the close log; `architecture.md`, Connections) are one
  named function, so the upgrade handler reads as its steps.

Tests: the existing tests pass, changed only where an import moves.

Check: `npm run check`, `npm run lint` and `npm run test` pass.
